## Fixed in this pass

1. **`favicon.ico` returned 404 on every page load.** Added `src/app/icon.svg`;
   Next.js now emits a proper `<link rel="icon">`. Production console is clean.
2. **The declared body font was never loaded.** `globals.css` asked for `Inter`
   but nothing imported it, so the app silently fell back to Segoe UI on
   Windows and to a different face elsewhere. Fonts are now loaded through
   `next/font/google` (no new package) with explicit fallback stacks.
3. **`dataMode` was in the type contract but rendered nowhere.** Both
   `PetViewModel` and `CommunityViewModel` carry `dataMode`, and
   PROJECT_BRIEF's completion criteria require the demo to distinguish live
   state from previews. A shared `DataModeBadge` now renders it on the pet
   scene and the community panel.
4. **The reason care totals are unknown was hidden in development.** The
   explanatory note lived in the `else` branch of a `NODE_ENV` check, so it
   appeared only in production while developers saw a bare "Unknown". The note
   now renders in every environment; only the preview links are gated.
5. **`/pet` was a dead end.** It stated that the pet home is not live and
   offered no way back. It now explains what is missing, lists the rules the
   page will enforce (sourced from `src/lib/pet-progress.ts`, not retyped), and
   links back to the overview.
6. **Misleading next-stage copy.** The pet scene said "50 points needed for the
   next stage" while showing 20 points, which reads as "50 more". It now reads
   "20 of 50 points toward Buddy."
7. **Unknown progress looked like zero progress.** An unknown total or missing
   target previously rendered no bar at all, or an empty track. Unknown states
   now render a hatched indeterminate track that cannot be mistaken for a
   zero fill, while still refusing to invent a percentage.
8. **No `sizes` on responsive `next/image` usages**, so full-resolution art was
   served to phones. Added on the hero and pet-scene images.
9. **No `metadataBase`, OpenGraph or Twitter metadata.** A submitted link
   previewed as nothing. Added, driven by `NEXT_PUBLIC_SITE_URL`.
10. **No dark-mode handling.** The app forced a light palette regardless of OS
    preference. A full dark token set is in place; contrast was checked for
    every text/background pair introduced.
11. **Reduced motion was only honoured in two component stylesheets.** It is
    now a global rule, so any future animation inherits it.
12. **Stale records in `docs/DEV_SETUP.md`**, which claimed "1 test file and 1
    test" when the suite has 5 files and 20 tests, and reported the favicon 404
    as an accepted condition. Corrected.

## Resolved after the first pass

- **Findings 1 and 2 (`PetRegistry.care()`) are fixed.** `unchecked` was
  removed so both increments use checked arithmetic, and the dead
  `lastCareDay != 0` sentinel was replaced with `pet.careCount != 0`, which
  states the real rule ("has cared before, and that care was today") without
  depending on `utcDay` never being 0. Measured on the existing tests:

  | Variant | First care | Two cares |
  |---|---|---|
  | Before (old guard, `unchecked`) | 119,875 | 155,697 |
  | New guard, still `unchecked` | 119,836 | 155,687 |
  | New guard, checked (shipped) | 120,469 | 156,953 |

  The guard change is free — marginally cheaper, since `careCount` shares a
  storage slot with `lastCareDay`. Checked arithmetic costs about **633 gas
  per care call**. Four boundary tests were added; the suite is 13/13.

- **The contract suite could not previously be run.** Foundry 1.8.3 was already
  present at `~/.foundry/bin` but absent from PATH, so `forge` looked
  uninstalled. The directory was added to the persistent user PATH; no
  reinstall was needed. Teammates who only touch UI do not need Foundry, so
  `npm run test:contracts` is lead-only in practice.

## Open findings — not fixed, needs a decision

1. **`communityStats()` reverts for an unapproved community id.** A reverting
   view is awkward for a UI that must distinguish "unknown" from "zero"; the
   L2 read layer must catch this and map it to unknown rather than 0.
2. **`PetScene` and `CarePanel` use hardcoded element ids** (`pet-name`,
   `care-heading`). Rendering two instances on one page would duplicate ids.
   Not currently reachable; worth a `useId()` if the profile stretch ships.
3. **`next-env.d.ts` flips between `.next/types` and `.next/dev/types`**
   depending on whether `next dev` or `next build` ran last, so it shows as a
   modified file constantly. Consider gitignoring it or committing one variant
   and leaving it alone.

## Not a finding

- Preview routes are genuinely excluded from production: the `/dev` layout
  calls `notFound()` before rendering children, and the production build
  returns 404 for all three. Verified again in this pass.
- No secrets, keys, addresses or `.env` values appear anywhere in the
  repository. `src/lib/deployment.ts` deliberately holds `null` instead of a
  placeholder address.
